# 选题库工作流

## 固定栏目

| ID | 栏目 | 选题边界 | 封面场景 |
|---|---|---|---|
| foundations | 基础认知 | 概念、症状、病理机制、疾病关系 | 人物、身体、器官与简化机制 |
| food-movement | 饮食运动 | 食物、进餐、活动和运动研究 | 餐桌、备餐、饭后散步、训练 |
| behavior | 行为管理 | 目标、习惯、睡眠安排、记录和复盘 | 日程、睡前准备、行动与记录 |
| monitoring | 指标监测 | 检查、CGM、手表戒指数据、误差 | 人与设备、曲线与测量场景 |

睡眠选题按重点归类：生理机制归基础认知，睡眠安排归行为管理。优先沿用用户已有栏目，不为适配分类改写选题。

## 个人库独立存放

`python3 scripts/init_library.py --out /path/to/my-redbook-library`

生成 topic-bank.csv、series-profile.json、inbox/ 和 posts/。不放在技能安装目录，不随技能发布到公开仓库。以后指定同一个库，沿用原ID、备注和制作状态；技能升级不覆盖个人库。多库时使用当前项目已指定的库，不悄悄合并。

每篇放在 `posts/<topic-id>/`，原始材料放其 sources/，成品放 output-v1/ 等版本目录。CSV 的 output_path 用相对库路径，source_ids 关联该篇 evidence.json。素材未用于本篇时，保留在 inbox 等待后续选题。

初次使用复制个人 series-profile.json 到每篇项目；new_post.py 默认复制的是技能模板，调用智能体需要用个人配置替换这份新建副本。先读已有CSV再更新，保留未知列与个人备注，更新前保存一份备份，写入后检查ID唯一且未丢行。

## 新建与维护

1. 新建时复制 `assets/topic-bank.csv` 至工作项目；种子库内容是问题，不是已验证答案。
2. 增加选题先按问题和受众去重。避免同一研究拆出多篇内容高度重复的笔记。
3. 每条有稳定ID、栏目、读者问题、搜索线索、状态与下一步；新增记录分配新ID，已有ID不重排。
4. 精选排期时看：目标读者相关性、证据是否足够、行动价值、与近期内容的重复程度、制作成本。推荐前10–12篇，后续按反馈调整。没有平台样本时不承诺爆款、不虚构流量阈值。
5. 用用户提供的数据复盘收藏/阅读、关注/阅读、相关评论主题；不同曝光基数要一起看。不把选题质量分数当预测流量的统计模型。

## CSV状态

`idea → researching → evidence-ready → drafting → reviewed → designed → exported → published`

- 状态反映实际完成阶段。发了文件给用户是exported，不是published。
- 用户修改结论时，相关内容回到drafting；仅改排版不使已核验来源失效。
- `published`只在用户确认发布或实际获授权发布成功后使用。
- `source_query`是检索线索，`source_ids`关联项目证据表；禁止把检索关键词当文献引用。
- 每次维护报告新增、更新、保持不动的范围，不覆盖未请求的个人备注。
