# 一张截图生成一篇笔记

用户只发一张内容截图时，默认完成整篇，不止返回大纲。读取图片可见内容，并沿用当前系列与用户已确认的偏好；看不清的引用先保存在内部待核对字段，不猜题名或数字。

## 取材与组织

1. 将截图复制到该笔记的 sources 目录。分离正文、研究结果、机制、引用标签和证据等级；用证据表把截图中的信息与成品逐条对应。
2. 从材料里选一个读者问题。已有选题库先查重，有对应主题就关联原ID；截图包含几个独立主题时，先完成最完整的一篇，其余登记候选题。
3. 通常做6–9页：问句封面、证据强度或研究概况、若干主题页、重点整理。每主题优先保留具体表现＋研究细节＋机制或实际意义。不要为了套满页数发明内容。
4. 对有信息的长截图，先列“保留/合并/另篇”的信息清单，再编辑，避免把丰富材料压成症状目录。没有材料支持的数字和机制不补写。
5. 生成主题匹配的无字动画插画，套用系列字体、页脚和栏目标签；内页使用直接标题。保留已接受的封面时不重复生成图。
6. 完成内容审核、导出与视觉检查，交付PNG、总览和发布文案。把来源状态与修改记录留在项目内部，读者内容中只出现有用的论述和引用。
7. 更新个人库的选题状态、来源ID、输出路径。仅导出就记 exported；实际发布后才记 published。

## 一句话调用

> 用 $redbook-create，把这张截图做成一篇完整笔记，沿用我的内容库与栏目风格，信息丰富一些，完成后更新选题库。

若截图太短，完成合理长度的笔记；若关键文字不可辨认且决定结论，先完成不依赖它的部分，再请用户补充该段文字。来源不完整不应变成每页重复的读者提醒，也不能变成编造书目。
